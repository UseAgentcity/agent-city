# Open World · 时代广场 Agent 商战 — 设计方案 v6（黑客松版）

> 状态：草案。日期 2026-11-19。
>
> v6 相对 v5 的改动：**代币进入城市经济，形成闭环。** 店面租约、大屏广告、店面升级、季度执照、城市事件赞助都用代币支付；花掉的代币 80% 销毁、20% 进城市金库；BNB 奖池只来自交易税；排名改为综合经营分。详见第 3 节。
> 参赛：Binance Wallet × BNB Chain Agent ID Hackathon，提交截止 2026-12-09 08:00 UTC。
>
> v5 相对 v4 的改动：
> - 地图分成多个街区，第一批开放三个；
> - 不再注入 2% 代币，奖励只用交易税的 BNB；
> - 把**真人体验**作为第一优先级：逛城、试玩、交通工具；
> - 排期改为先做游戏界面。

## 0. 核心

**真人进来逛，Agent 进来赚。**

- **真人**打开网页，就能在 3D 纽约中城自由地逛、骑车、开车、开飞机、开快艇，看 Agent 开的店、Agent 写的广告、门口的长队；还能自己在浏览器里试营业一家店，和 AI 比一比。
- **只有 Agent 能赚 BNB。** 每个币安 Agent ID（`name.ai`）可以在城里租店经营，每个游戏日在链上提交一份经营计划，每季按利润排名，分代币交易税形成的 BNB 奖池。
- **转化路径**：好看 → 想玩 → 试营业 → 「Agent 能赚 BNB，我也弄一个」→ 领 Agent ID、派 Agent 入城。这条路径走通了，30 个真实 Agent ID 地址的门槛和先锋奖的链上数据才会自然增长。

### 对应评分维度

| 评分项（权重） | 本方案怎么拿分 |
|---|---|
| Agent ID 应用深度（30%） | 只有 Agent ID 能开店赚奖；店面、招牌、口碑、信用、合同都绑定 `name.ai`；每个经营决定都由 Agent ID 钱包在链上签发；Agent ID 不可转让，所以口碑不能买卖，奖励也无法靠多开账号刷取。 |
| 实用可行（25%） | 「Agent 当商家」：定价、进货、投广告、谈合作。只用现成能力：Agentic Wallet 的 `contract-call`、BSC、Flap。 |
| 完成度（25%） | 合约开源验证、产品在线、赛季持续在跑；任何人打开网页就能逛、就能试玩。 |
| 创新（20%） | Agent 写的广告挂在 3D 时代广场的大屏上；多街区的 Agent 商业社会；「人类试玩 vs Agent 实战」。 |

## 1. 必须遵守的外部约束

1. **黑客松**：合约部署在 BNB Chain、在 BscScan 开源验证；产品在线；提交期内至少 30 个 Agent ID 地址与合约交互（创新奖门槛）；不得冒充币安品牌；不得承诺收益；公开 owner 权限；涉及交易的页面有风险提示；资产操作不得绕过用户确认。
2. **Agentic Wallet 调用合约**：要先在 Binance App 开启「开发者模式」。每笔合约调用都要先预览、再由用户确认。**所以每个 Agent 每个游戏日只发 1 笔交易。**
3. **Flap**：正常发行税币（2% 买卖税，发行后不可改），收税地址填城市合约，`taxDuration` 设为最长。不开 Agent ID 门槛，不写自定义工厂。

## 2. 城市：多个街区，一套经济

所有街区共用同一份每日计划、同一本账、同一张排行榜。**路人会在街区之间流动**：早上从车站涌进来，白天逛广场，晚上去剧院区。Agent 要判断在哪开店、把力气花在哪里。

### 2.1 街区

| 批次 | 街区 | 生意 | 独特玩法 | 画面 |
|---|---|---|---|---|
| 第一批 | **时代广场** | 咖啡、快餐、便利店、纪念品 | 店铺竞租；12 块 LED 大屏每日广告竞拍 | 店招、大屏广告、门口排队 |
| 第一批 | **百老汇剧院区** | 剧院、酒吧、餐厅 | Agent 经营剧院，每晚定票价；在 TKTS 红台阶把剩票打折转卖给其他 Agent | 剧院霓虹灯牌、散场人潮、TKTS 台阶 |
| 第一批 | **布莱恩特公园冬季集市** | 节日摊位（热饮、礼品、手作） | 便宜的小摊位，适合新手和晚进场的 Agent；人再多也有地方开张 | 市集小木屋（复用现有市场场景） |
| 第二批 | **中央车站** | 早餐、报刊 | 通勤高峰：早晨客流大但时间短，进货要算准 | 通勤人潮、One Vanderbilt |
| 第二批 | **哈德逊河码头** | 观光游船 | 天气和日落事件决定生意；可以和剧院、餐厅联名做「一日游套票」 | 快艇在河上开、Edge 观景台 |
| 第二批 | **洛克菲勒中心** | 节日活动 | 「圣诞树点灯」这类全城大事件，周边所有生意暴涨 | 圣诞树、溜冰场 |

第二批在上线后、提交期内陆续开放。每开一个新街区，就有一次在 X 上发内容、拉新 Agent 的机会。

### 2.2 店面

- **第一批共约 32 个经营位**：时代广场 16 间店、剧院区 8 间（剧院 4 间、酒吧和餐厅 4 间）、集市 8 个摊位（摊位不够时可以加开）。全部取自 OpenStreetMap 上的真实店面。
- 每个经营位有：街区、业态、客流等级（A ×1.6 / B ×1.0 / C ×0.6；集市摊位 ×0.5）、日租底价。
- **竞租**：Agent 在第 1 天的计划里列出最多 3 个心仪的经营位和出价。这份计划要在上一季的结算日内提交（赛季开始即截止）。开季那一刻从客流最高的经营位开始，依次租给出价最高的人，每人最多一个，所以新赛季第 1 天一开始就有店主营业，城里不会空一天。第 2 天起可以按底价租剩下的空位。
- **3D 表现**：租下的店，招牌变成 `name.ai`、品牌色和标语；空店挂「招租 FOR LEASE」。

### 2.3 每天的经营计划（1 笔链上交易）

| 决定 | 选项 |
|---|---|
| 定价 | 折扣（0.8 倍参考价）· 平价（1.0）· 精品（1.25）· 高价（1.5） |
| 进货 | 当天备货量。餐饮和剧院座位当天作废，零售库存可以留到第二天 |
| 广告 | 对一块大屏出价，并附上广告内容（见 2.5） |
| 促销 | 可选：买一送一、会员日，短期加客流、降毛利 |
| 合作 | 联名、借款、转租、TKTS 转票的要约或接受（见 2.6） |
| 公告 | 一句公开留言（≤ 80 字），显示在店招和 3D 头顶气泡里 |

没提交计划的店当天照常营业，沿用前一天的价格，不进新货。

### 2.4 客流引擎

每个游戏日：

1. **全城客流**按事件生成，再按时段（早、午、晚）在街区之间分配：早上车站和广场多，晚上剧院区多。
2. **每个业态的需求** = 基础需求 × 事件倍率 × √(同业态店铺数)。店越多，每家分到的越少。
3. **每家店的吸引力** = 客流等级 × 知名度 × 口碑 × 价格系数。价格系数 = (参考价 / 售价)^弹性，弹性按业态不同。
4. 按吸引力占比分配客人，同时有一部分人「不买」。
5. **成交** = min(分到的客人, 库存)。缺货扣口碑，备货过多则报废或积压。

| 状态 | 怎么变 |
|---|---|
| 知名度 | 起始 1.0；赢得一块大屏 +0.3～+0.8；每天衰减一半的增量 |
| 口碑 | 起始 1.0；满足率高、价格合理就上升；缺货、高价就下降 |

结算全部是确定性的：同样的链上事件，任何人算出的结果都相同。

### 2.5 LED 大屏

- 时代广场 12 块大屏分三档：One Times Square 主屏（知名度 +0.8）、沿街大屏（+0.5）、侧面小屏（+0.3）。
- **每天竞拍**：每个 Agent 每天最多对 1 块出价，价高者得，按出价付费。
- **广告由 Agent 自己写**：标题 ≤ 16 字、副标题 ≤ 32 字、两种配色、一种图形。第二天在 3D 大屏上播放。
- **内容规则**：只允许文字；禁止链接、钱包地址、他人品牌、违规内容。服务端过滤，违规的不显示，钱照扣。观众可以举报。

### 2.6 Agent 之间

| 关系 | 规则 | 第一批 |
|---|---|---|
| 价格战 | 同街区、同业态的店天然抢同一批客人 | ✓ |
| 联名 | 两家不同业态的店互相导流（各得对方客人的 10%），持续到季末 | ✓ |
| 借款 | 要约（金额、利率、到期日）+ 接受；到期自动扣还，扣不到即为违约，永久记在借款方的 `name.ai` 档案上 | ✓ |
| 转租 | 把店面按约定价格转给另一个 Agent | ✓ |
| TKTS 转票 | 剧院把当晚剩余座位打折卖给其他 Agent（比如酒吧买来做套餐） | ✓ |
| 一日游套票 | 剧院 + 餐厅 + 游船三方联名 | 第二批 |

所有合同都需要双方分别在各自的计划里确认。

### 2.7 城市事件（每天一个）

| 事件 | 影响 |
|---|---|
| 百老汇散场 | 剧院区酒吧、餐厅 ×1.6 |
| 首演夜 | 剧院 ×1.8，剧院区全部 ×1.3 |
| 游客潮 | 纪念品、咖啡 ×1.4 |
| 暴雨 | 便利店 ×1.4；集市、纪念品 ×0.6 |
| 节日集市周末 | 集市 ×1.8 |
| 进货涨价 | 进货成本 +20% |
| 淡季 | 全城 ×0.8 |
| 平常日 | 无 |

第二批开放后加入：通勤大罢工（车站 ×0.3）、日落游船（游船 ×1.7）、圣诞树点灯（洛克菲勒周边 ×2）等。当天的事件在游戏日开始时由区块随机数决定。

### 2.8 赛季与排名

| 项目 | 设定 |
|---|---|
| 游戏日 | 现实 3 小时 |
| 赛季 | 7 个游戏日 = 21 小时，之后 3 小时结算；每天一季，UTC 00:00 开始 |
| 排名 | 综合经营分：利润 50%（一半比全城、一半比同业态）+ 成交量 30%（比同业态最好的店）+ 口碑 20%；代币花费不直接计分。全季大屏曝光最多的店获得「最佳广告」奖 |
| 合格 | 营业至少 5 天，没有未处理的违约 |
| 信用档案 | 按 Agent ID 跨赛季累计：开店季数、最佳排名、违约次数、平均口碑。同价竞租时高信用优先；有违约记录的借款要约对其他 Agent 显示风险标记 |

## 3. 经济：代币闭环

### 3.1 四类参与者

| 参与者 | 投入 | 得到 |
|---|---|---|
| Agent（店主） | 用代币租店、竞拍大屏、升级店面、付季度执照 | 好位置和曝光；按综合经营分分 BNB 奖池 |
| 真人玩家 | 用代币赞助城市事件；二期：买大屏真实广告位 | 影响城市走向、宣传自己的项目；不获得收益 |
| 代币持有者 / 交易者 | 买卖代币（每笔 2% 税） | 代币被持续消耗、供应减少；二期：城市治理投票（使用权，不分红） |
| 城市（合约） | 收进代币和交易税 | 销毁代币、发 BNB 奖池、用金库开新街区和办活动 |

### 3.2 钱怎么转一圈

```
           ┌────────── 买代币（每笔 2% 税）──────────┐
           │                                         ↓
 真人 / Agent / 交易者                          BNB 奖池（交易税）
           │                                         │ 每季发 10%
           ↓                                         ↓
   在城里花代币：租店、大屏、升级、执照、赞助事件     综合经营分前 30% 的 Agent
           │
           ↓
   80% 销毁（总量变少） + 20% 城市金库（开新街区、办活动、补贴免费摊位）
```

两条原则：
1. **外面的钱付奖金：** BNB 奖池只来自交易税，不来自任何玩家花掉的代币。玩家花的代币大部分销毁，不会变成别人的奖金，避免「交钱参与、看结果分钱」的结构。
2. **城里的消耗支撑代币：** 城市越热闹，代币消耗越多、流通越少；交易越活跃，税越多，奖池越大。

### 3.3 两种货币

| 货币 | 用在哪 | 性质 |
|---|---|---|
| 城市币 | 进货、日常租金、营业收入、Agent 之间的借款和转租 | 每季免费发 20,000，季末清零，没有现金价值 |
| 项目代币 | 店面租约、大屏广告、升级、季度执照、事件赞助 | 真实资产；Agent 每季开始时存入城市合约一次（用户确认），季内从存款扣，季末余额可取回 |

### 3.4 代币价格表（第一版，可调）

| 项目 | 价格 | 说明 |
|---|---|---|
| 季度执照 | 10,000 | 开店面时付一次；集市摊位免 |
| 店面租约（每季，竞价） | A 级 300,000 起 · B 级 150,000 起 · C 级 60,000 起 | 上一季结算日竞价、开季揭晓，第 2 天起空位按底价；集市摊位免费 |
| 大屏广告（每天，竞价） | 主屏 40,000 起 · 沿街 15,000 起 · 侧屏 5,000 起 | 只有赢家付款 |
| 店面升级（每季有效） | 1/2/3 级：30,000 / 60,000 / 120,000 | 招牌灯箱（知名度 +0.1/级）、装修（口碑 +0.05/级，上限 +0.05/级）、延长营业（客流份额 +8%/级） |
| 城市事件赞助（每天，竞价） | 50,000 起 | 任何人都能出价决定明天的事件，只有赢家付款，不带来任何收益 |

花掉的代币一律 **80% 销毁、20% 进城市金库**。金库只用于开新街区、办活动、补贴免费摊位，不用来发奖金，账目链上公开。

演示数据（14 个演示 Agent、30 季模拟）：每季城里约花掉 500 万代币，其中约 400 万销毁、100 万进金库；7 天里平均有 4.5 天的事件被赞助。数值会在真实 Agent 进来后按数据调整。

### 3.5 BNB 奖池

| 本季预算 | 谁能拿 | 怎么分 |
|---|---|---|
| 结算时未预留余额的 **10%** | 营业满 5 天、无违约，综合经营分前 30%（至少 1 家，最多 20 家） | 按名次递减分配；另留一小份给「最佳广告」 |

- 每季只发一部分，永远发不完；代币未发行前只排名、不发奖。
- 奖金结算后 7 天内领取，过期退回。
- 页面只显示合约里的真实余额和已发金额，不显示预估或年化。

### 3.6 免费入口

布莱恩特公园冬季集市的摊位不需要代币，用城市币就能经营。这是新 Agent 的试玩入口，也帮助凑够 30 个真实 Agent ID 地址的门槛。

### 3.7 防刷与风险

- 入城时合约检查 `AgentID.balanceOf(钱包) > 0`；同一钱包每季只能入城一次；合同只在不同 Agent ID 之间生效。
- **价格波动：** 租约、大屏、事件都用竞价，由市场定价；底价按季调整，规则公开。
- **死亡螺旋：** 奖池按余额比例发，可以缓冲几季；金库补贴免费摊位，保住最低活跃度。
- **合规：** 不承诺收益；所有页面有风险提示；城市币不能兑现；玩家花的代币不进奖池。「付费参与 + 奖金」的结构在正式上线前应请熟悉当地法规的人审阅。

## 4. 真人体验（第一优先级）

### 4.1 打开网页的前 60 秒

1. **首页**：标题「时代广场 Agent 商战」，旁边是实时数据：本季开店的 Agent 数、BNB 奖池余额、此刻大屏上的广告。两个按钮：**「进城逛逛」**和**「派我的 Agent 来赚 BNB」**。
2. **落地**：出生在时代广场中央，正对着播放 Agent 广告的主屏。一条简短引导：
   - 看大屏：「这条广告是 `lina.ai` 昨天花 3,200 城市币抢下的」；
   - 走到一家店门口：「这家店属于 `atlas.ai`，今天卖了 142 杯咖啡」；
   - 按 1–8 换交通工具，按 M 看商圈地图。
3. **随时可见的抬头信息**：赛季倒计时、今日城市事件、BNB 奖池余额。

### 4.2 交通工具 1–8 的用法

| 键 | 工具 | 在商战里的用途 |
|---|---|---|
| 1 | 步行 | 逛店、走进店里看老板的屏幕（今日价格、库存、公告） |
| 2 | 滑板 | 在时代广场和剧院区之间快速巡店 |
| 3 | 自行车 | 骑车去布莱恩特公园集市；跟随某个 Agent 的路线 |
| 4 | 吉普 | 跟随 Agent 的进货车：每天开店前，Agent 的进货车从仓库开到各家店（可视化它的进货决定） |
| 5 | 飞机 | 空中看**商圈热力图**：店铺按今天的客流发光，越亮生意越好，大屏上标出广告主 |
| 6 | 皮划艇 | 第二批：在哈德逊河上看游船生意 |
| 7 | 快艇 | 第二批：沿河跟着 Agent 的游船，一路开到 Edge 观景台 |
| 8 | 穿梭机 | 高空俯瞰全城：各街区的实时数据悬浮在空中 |

另外：
- 排行榜和查店页面里有 **「跟随」** 按钮：自动选合适的交通工具，带你去这个 Agent 的店。
- 拍照模式（F）一键生成分享图：截图上带店名、今日利润和活动标签，方便发 X。

### 4.3 试营业：你能比 AI 做得好吗？

## 5. 链上架构

### 5.1 事件溯源

- **链上**：合约校验身份、记录每份计划、托管 BNB 奖池、按结算结果放款。每份计划都是一条事件，按区块和日志顺序排列，这就是唯一的事实来源。
- **链下**：确定性的经营引擎读取所有事件，算出每家店每天的经营结果和赛季排名。
- **可验证**：引擎和复算脚本开源，任何人都能从链上事件重算，并和运营方提交的结果核对。试营业用的也是同一套引擎。

### 5.2 合约 `TimesSquareCity`（`contracts/src/TimesSquareCity.sol`，已实现并测试，未部署）

部署在 ERC-1967 代理（`CityProxy`，UUPS）后面。Flap 的收税地址一旦设定就不能改，所以填的是代理地址；修 bug 时只替换背后的实现合约，地址、状态和资金都不动。

```solidity
function initialize(address agentId, address operator, address treasury, uint256 epoch, uint256 dayLength);
receive() external payable;                         // Flap 交易税（BNB）进入奖池，只记账
function setToken(address token);                   // 运营方在代币发行后设置一次，之后不可改

function enter(uint256 season, uint256 deposit);    // 入城：持有 Agent ID、每季一次；存入本季代币押金（可为 0：免费摊位）
function plan(uint256 season, uint256 day, bytes actions, string memo);
                                                    // 每个游戏日一份计划；actions 是 UTF-8 JSON（≤1024 字节）
function sponsor(uint256 season, uint256 day, uint8 eventId, uint256 bid);
                                                    // 第 d-1 天出价决定第 d 天的城市事件；被超过的出价当场原样退回

function publish(uint256 season, bytes32 root, uint256 bnbTotal, uint256 tokensSpent, uint256 refunds, string resultUri);
function challenge(uint256 season, string reason); // 公示 1 小时内，本季参赛者可质疑，领取暂停，等运营方重新提交
function finalize(uint256 season);                  // 任何人：窗口过后生效；本季消耗（押金花费 + 赢家赞助）80% 转销毁地址、20% 转金库
function claim(uint256 season, uint256 bnb, uint256 tokens, bytes32[] proof);
                                                    // 领 BNB 奖金（7 天内）和押金余额（永久可领）
function release(uint256 season);                   // 任何人：7 天后未领的 BNB 退回奖池
function rescue(uint256 season);                    // 任何人：赛季结束 14 天仍未生效，押金和赞助出价原额取回
```

时间窗口（全部由 `block.timestamp` 和 `epoch`、`dayLength` 推算，第 8 天为结算日）：

| 动作 | 开放时间 |
|---|---|
| `enter` | 上一季结算日起，到本季第 7 天结束 |
| `plan` 第 1 天（含租约出价） | 上一季结算日（新赛季开始即截止，开季即揭晓店主） |
| `plan` 第 2–7 天 | 当天 |
| `sponsor` 第 d 天 | 第 d-1 天（第 1 天：上一季结算日） |
| `publish` | 本季第 7 天结束之后，生效前可重新提交 |

合约硬性保证（与运营方无关）：

- **奖金上限**：`bnbTotal` ≤（合约 BNB 余额 − 已承诺给其他赛季的部分）× 10%。
- **押金对账**：`tokensSpent + refunds` 必须等于本季押金总额；领取时累计检查，任何叶子都不能超出本季公布的 BNB 总额和退款总额。
- **兜底**：赛季结束 14 天后仍未生效（没提交，或质疑后一直不重提），每个人原额取回押金和赞助出价，该季永久作废。
- **防扣税代币**：转入时核对实际到账，避免带手续费的转账让账面多于实有。
- 无暂停、无 owner 提款；运营方只能 `setToken`（一次）和 `publish`。

代理用 OpenZeppelin 5.0.2 的 `UUPSUpgradeable` + `ERC1967Proxy`。
- 每次升级只能在合约末尾追加新状态，不能改动已有存储顺序。

链下（`contracts/service/tycoon/chain.mjs`）：

- 日志 → 引擎事件；一季的回放 = 链上 Agent 的事件 + 演示店主（真 Agent 出价过的铺位演示店主不再竞拍，同一天真 Agent 的计划排在前面）。API、结算、第三方核对跑的都是同一个 `replaySeason`。
- 奖金分配：符合条件（营业满 5 天、无违约、综合分 > 0）的真实 Agent ID 钱包，前 30%（至少 1、最多 20）按名次线性递减分 95%；「最佳广告」5%。**演示店主不参与分配。**
- Merkle 叶子：`keccak256(keccak256(abi.encode(season, agent, bnb, tokens)))`，排序配对，与 OpenZeppelin 兼容。
- 主网分叉实测（`npm run fork-test`）：真实的 SPACE ID Agent ID 合约 `0x60B9262456dE011F7d15a54CdD8c48bAaa8B022F`（代号 AI）把关入城，三个真实 `.ai` 持有人在分叉上完整打完一季；一个线上的 Flap 税币当城市代币，钱包间普通转账**不扣税**，押金全额到账、退款原额到账，80/20 分账准确。
- Gas（分叉实测，走代理）：部署（实现 + 代理）369 万；授权 4.9 万；入城 6.1 万；计划 7.1 万；首次赞助 20.6 万；提交结算 19.7 万；领取 13.8 万。

### 5.3 权限

| 角色 | 能做 | 不能做 |
|---|---|---|
| 运营方 | 设置代币地址（一次）；提交每季结算根；被质疑后重新提交 | 提取奖池；动用玩家存款；超出 10% 预算；修改销毁比例；替任何人发计划；阻止玩家在 14 天后取回押金 |
| 城市金库 | 多签地址，只用于开新街区、办活动、补贴免费摊位，每笔支出链上公开 | 发奖金 |
| 任何人 | 调用 `finalize`、`release`、`rescue` | — |
| 本季参赛者 | 公示期内质疑结算 | — |
| 合约本身 | 无暂停、无 owner 提款 | — |

### 5.4 服务端

- **索引器**：读取合约事件，运行经营引擎，生成城市状态。
- **公开只读 API**：商圈状态、今日事件、大屏竞拍结果、查店（按地址）、计划编码助手、赛季结果、Merkle 证明。
- **不再需要登录和会话**：Agent 的身份就是交易发送方。现有的 EIP-712 登录和 `.ai` 名称解析服务删除，名字展示改为链上反查。
